SQL Interview Question Study

	- Normalization
	
		- reduces redundancy and update/insert/delete anomalies by splitting data into tables while retaining the original meaning

	- Normal Forms
	
		- 1NF: requires each column to hold atomic values with no repeating groups
		
		- 2NF: 1NF plus no partial dependence on a composite primary key; every non-key must depend on the whole key
		
		- 3NF: 2NF plus no transitive dependencies; non-keys depend only on the key and not other non-keys
		
		- BCNF: strengthens 3NF; for every functional dependency X -> Y, X must be a candidate key (fixes edge cases like overlapping keys)
		
		- 4NF: removes multi-valued dependencies
		
		- 5NF: eliminates join dependencies, decomposing so tables can be losslessly recombined without spurious tuple
	
	- UNION and UNION ALL
	
		- UNION combines the results of two queries without duplicates
		
		- UNION ALL is the same as union but faster at the cost of including duplicates
	
	- CTEs (Common Table Expressions)
	
		- temporary named result defined with WITH that exists only for the duration of a single statement		
	
	- Pattern Matching (LIKE)
	
		- LIKE and NOT LIKE functions allow for pattern matching
		
	- EXISTS and NOT EXISTS vs IN
	
		- EXISTS/NOT EXISTS use a correlated subquery and are robust with NULLs
		
		- NOT IN is NULL-sensitive if the subquery can yield NULL, NOT IN may return no rows (unknown comparisons), so prefer NOT EXISTS
		
		- performance varies EXISTS often wins for large subqueries with indexes; IN is fine for small, deduplicated lists
	
	- Subqueries
	
		- correlated subquery: subquery that depends on the current row of the outer query
	
	- Anti-JOINs
	
		- returns rows from one table (LEFT) with no matching rows in another table (RIGHT) based on a join condition (ex: in A but not B)
	
	- RANK(), DENSE_RANK(), ROW_NUMBER()
	
		- RANK(): assigns the same rank to tied rows but leaves gaps after ties
		
		- DENSE_RANK(): assigns the same rank to ties but doesn't leave gaps.
		
		- ROW_NUMBER(): assigns a unique sequential number to each row within a partition based on the order; no ties share a number

	- Cross JOIN
	
		- returns the cartesian product of two tables
		
		- every row from LEFT paired with every row from RIGHT
	
	- UNION, INTERSECT, and EXCEPT
	
		- UNION: merges similar data from multiple sources
		
		- INTERSECT: returns only rows common to both queries
		
		- EXCEPT: returns rows in the first query that aren't in the second
	
	- Database Partitioning
	
		- divides database into smaller sections to boost query speed while maintaining structure
	
	- denormalization
	
		- making a database more redundant to improve query performance
	
	- Indexes
	
		- clustered vs nonclustered
		
			- clustered: stores table rows in the physical order of the index key; can only have one; ideal for range scans and primary-key lookups
			
				- key is narrow, stable, and increasing (ex: order_id, order_date)
				
				- queries do range scans or ORDER BY on that key
			
			- non-clustered: separate structure (key -> row locator) and you can have many; accelerates specific filters, joins, and sorts without changing the table's row order
			
				- you need fast point looups or high-selectivity filters (WHERE email = ?)
				
				- columns are common JOIN/GROUP BY/ORDER BY targets
				
				- you can cover queries via INCLUDEd columns
	
	- cursors
	
		- database object used to retrieve, manipulate, and traverse through rows in a result set one row at a time
		
		- helpful for performing operations that must be processed sequentially rather than in a set-based manner
		
		- types of cursors
		
			- STATIC: snapshot of result set, does not reflect changes
			
			- DYNAMIC: reflects all changes made while the cursor is open
			
			- FOWARD_ONLY: can only move forward through the result set
			
			- KEYSET: uses a key to fetch rows; changes to non-key columns are visible
	
	- CASE statement
	
		- implements conditional logic in queries
		
		- returns a value based on the first condition that evaluates to be true; returns a default value if false using an ELSE clause
	
	- COALESCE
	
		- returns the first non-NULL value from a list of expressions
		
		- used to provide default values or handle missing data
	
	- NVL and NVL2
	
		- NVL(): replaces a NULL value with a DEFAULT value
		
		- NVL2(): returns one value if NOT NULL and another if NULL
	
	- scalar functions
	
		- LEN, ROUND, CONVERT
		
	- window functions
	
		- allow you to perform calculations across a set of table rows that are related to the current row within a result set, without collapsing the result set into a single row
		
		- can be used to compute running totals, moving averages, rank rows, etc.
	
		- LAG: lets you look at previous rows in the same result set without self joins
		
		- LEAD: same as LAG but looks at next rows
	
	- materialized view vs standard view
	
		- materialized is static and requires refreshing
		
		- standard is dynamic (real time)
		
	- sequence
	
		- database object that generates a series of unique numeric values
		
		- used to produce unique identifiers for primary keys or other columns requiring sequential values
	
	- MERGE statement
	
		- combines multiple operations INSERT, UPDATE, and DELETE into one
		
		- used to synchronize two tables by:
		
			- inserting rows that don't exist in the target table
			
			- updating rows that already exist
			
			- deleting rows from the target table based on conditions
			
			- can cause concurrency issues
	
	- ACID
	
		- Atomization: transaction is treated as a single unit of work, all operations succeed or fail as a whole
		
		- Consistency: transaction must take the database from one valid state to another, all rules and constraints are maintained
		
		- Isolation: transactions shouldn't interfere with each other
		
		- Durability: once a transation is committed, its changes must persist, even in the event of a system failure
		
	- WITH (NOLOCK) hint
	
		- allows a query to read data without acquiring shared locks, effectively reading uncommitted data 
	
	- deadlocks and livelocks
	
		- deadlocks: occur when two or more transactions are waiting on each other's resources indefinitely, blocking all progress
		
		- livelocks: occur when two or more transactions are responding to each other's changes, but no progress is made; they keep running unlike deadlocks
	
	- pivot operator
	
		- switches rows and columns in a table
